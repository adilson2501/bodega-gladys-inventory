# Phase D.2: APF3 Model Training and Evaluation

## Scope and provenance

This phase trains two supervised regressors and evaluates them against two
historical baselines using only the frozen Phase D.1 artifacts. All results are
`SYNTHETIC`. No database, application endpoint, or source simulation is used.
No production inference API is created.

The target is completed sales units from `t+1` through `t+7`. Predictions are
clipped at zero because negative sales units are not meaningful.

## Temporal validation

The approved partitions are unchanged:

- Train: 2026-08-15 to 2026-09-20, 2,220 rows.
- Validation: 2026-10-01 to 2026-10-09, 540 rows.
- Test: 2026-10-16 to 2026-10-24, 540 rows.

Hyperparameter tuning uses two expanding chronological folds inside training:

- Fold 1: training through 2026-08-29; validation 2026-09-06 to 2026-09-12.
- Fold 2: training through 2026-09-05; validation 2026-09-13 to 2026-09-19.

The training cutoff is at least eight days before each validation cutoff. Thus
training labels are observable before validation prediction begins and target
windows do not overlap. Products for each date remain together.

## Baselines

- `naive_7d`: `7 * rolling_mean_7`, equivalent to the sum of completed units on
  `t-7` through `t-1`.
- `moving_average_14d`: `7 * rolling_mean_14`, the mean daily completed units
  on `t-14` through `t-1`, scaled to a seven-day total.

Both use exactly the same train, validation, and test rows as the regressors.

## Models and tuning

Ridge uses a training-only `ColumnTransformer` with median numeric imputation,
standard scaling, most-frequent categorical imputation, and
`OneHotEncoder(handle_unknown="ignore")`. The alpha search space is
`[0.1, 1.0, 10.0, 100.0]`.

Random Forest uses training-only imputation and one-hot encoding, fixed
`random_state=42`, `n_jobs=1`, and the following small grid:

- `n_estimators`: 100, 200
- `max_depth`: None, 8
- `min_samples_leaf`: 1, 3
- `max_features`: 0.7

The validation selection criterion was MAE among Ridge and Random Forest only.
Ridge with `alpha=10.0` was frozen before test evaluation.

## Executed metrics

| Model | Train MAE | Validation MAE | Test MAE | Test RMSE | Test R2 | Test WAPE | Test bias |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Naive 7d | 1.4207 | 1.3981 | 1.3870 | 2.0874 | 0.2989 | 0.6175 | -0.0389 |
| Moving average 14d | 1.2448 | 1.2769 | 1.3120 | 1.8645 | 0.4407 | 0.5841 | -0.1009 |
| Ridge | 1.0405 | 1.2375 | 1.2985 | 1.7314 | 0.5177 | 0.5780 | +0.0860 |
| Random Forest | 0.9098 | 1.2381 | 1.3313 | 1.8246 | 0.4644 | 0.5927 | -0.1019 |

Ridge beat the strongest validation baseline, moving average 14d, by MAE
`0.0393`. It was not changed after observing test results. On the untouched
test set, Ridge remained the lowest-MAE model among the four reported methods.

## Overfitting and errors

Random Forest has a larger train/validation MAE gap (`0.9098` to `1.2381`)
than Ridge (`1.0405` to `1.2375`), consistent with greater variance despite
the controls. Test MAE is not used for selection.

The three largest selected-model test errors are recorded in
`ml/artifacts/apf3/error_analysis.json`:

- Product `9569fc3f...`, cutoff 2026-10-21: actual 11, predicted 4.864,
  absolute error 6.136.
- Product `9569fc3f...`, cutoff 2026-10-22: actual 11, predicted 4.870,
  absolute error 6.130.
- Product `1c30d819...`, cutoff 2026-10-18: actual 1, predicted 6.512,
  absolute error 5.512.

These are descriptive errors. Intermittent demand and short synthetic history
are plausible explanations; no causal operational claim is made.

The exported Ridge coefficients are summarized in
`model_metadata.json` and plotted in `feature_importance.png`. Product-level
one-hot terms and category terms are prominent, which is expected for this
small multi-product panel and should not be interpreted as causal importance.

## Export and inference

The selected pipeline is exported to `ml/artifacts/apf3/model.joblib` after
test evaluation and refit on frozen train plus validation rows. Its metadata
contains the dataset hash, source provenance, periods, features, hyperparameters,
dependency versions, metrics, and model hash.

Offline inference is provided by `ml/infer_apf3.py`. It validates the generated
model hash, input schema, numeric values, ISO date, and `SYNTHETIC` provenance.
It does not accept a target field or modify stock.

## Reproduction

```bash
.venv/bin/pip install -r ml/requirements.txt
.venv/bin/python -m ml.train_apf3 \
  --artifact-dir ml/artifacts/apf3 \
  --output-dir ml/artifacts/apf3
.venv/bin/python -m ml.infer_apf3 \
  --model ml/artifacts/apf3/model.joblib \
  --metadata ml/artifacts/apf3/model_metadata.json \
  --input ml/artifacts/apf3/inference_example.json
.venv/bin/pytest ml/tests
```

The reported metrics and figures are generated by the training command; no
metrics are hardcoded in the trainer.

## Limitations

This is a 92-day synthetic experiment. It cannot establish real-world
predictive accuracy, savings, stockout reduction, or generalization to actual
customers. The two stockout-censored product-days may bias completed-sales
targets downward. Phase D.3, if authorized, should consider richer censoring
methods and additional real historical data before operational use.
